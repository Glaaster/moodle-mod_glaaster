Guide de Démarrage Rapide

Ce guide vous permet d'installer et configurer le plugin Glaaster en quelques minutes.

Prérequis​

Environnement serveur​

  • Moodle : 4.5, 5.0, 5.1, ou 5.2
  • PHP : 8.1, 8.2, 8.3, ou 8.4 (8.3+ requis pour Moodle 5.2)
  • Base de données : PostgreSQL ou MariaDB/MySQL
  • HTTPS : requis pour les lancements LTI 1.3
  • Extensions PHP :
    • php-curl
    • php-openssl
    • php-json
    • php-mbstring

Environnement de développement (optionnel)​

  • Node.js : 22.11+ (< 23)
  • Yarn : 4.9.1
  • Git : Pour cloner le repository

Installation en 3 étapes​

Étape 1 : Télécharger le plugin​

Option A : Via ZIP (production, recommandée)​

  1. Télécharger le ZIP de la release (mod_glaaster_v<version>.zip)
  2. L'installer via Site administration → Plugins → Install plugins, ou l'extraire dans moodle/mod/ (le ZIP contient un dossier racine glaaster/)
  3. Vérifier que version.php se trouve à moodle/mod/glaaster/version.php

Important : La structure correcte doit être :

moodle/
└── mod/
    └── glaaster/
        ├── version.php
        ├── lib.php
        └── ...

Sur Moodle 5.1+, le code web est sous moodle/public/ : le plugin va alors dans moodle/public/mod/glaaster/.

Option B : Via Git (développement)​

Le dépôt contient le plugin dans le sous-dossier mod/glaaster/ : ne pas le cloner directement dans moodle/mod/glaaster.

git clone https://github.com/Glaaster/moodle-mod_glaaster.git
# Copier (ou lier) le sous-dossier du plugin dans Moodle
cp -r moodle-mod_glaaster/mod/glaaster /path/to/moodle/mod/glaaster

Étape 2 : Installer le plugin dans Moodle​

Via l'interface : Site administration → Notifications

Ou via CLI :

php admin/cli/upgrade.php

L'installation crée automatiquement :

  • le rôle Glaaster API (glaasterapi, contexte système) ;
  • le service web Glaaster API (glaaster_api, utilisateurs autorisés uniquement) ;
  • le domaine d'outil par défaut lti.glaaster.com.

Étape 3 : Configurer Glaaster (administrateur)​

Tout se fait sur une seule page : Site administration → Plugins → Activity modules → Glaaster (/mod/glaaster/toolconfigure.php). La carte Glaaster API Setup affiche l'état de chaque élément (rôle, service, utilisateur API, token) et guide en 5 étapes :

  1. Create a dedicated user — créer un compte Moodle dédié à l'API (jamais utilisé pour se connecter en tant que personne réelle).
  2. Assign the API user — sélectionner ce compte. Le rôle Glaaster API (niveau système) et l'accès au service glaaster_api lui sont attribués automatiquement.
  3. Generate the API token — générer le token permanent du service glaaster_api.
  4. Connect — enregistrement dynamique LTI 1.3 (LTI Advantage) auprès de https://<tool domain>/register ; le token API est transmis automatiquement à Glaaster.
  5. Notify Glaaster by email — e-mail pré-rempli avec l'URL du Moodle, pour signaler l'activation de la connexion.

Aucune configuration LTI manuelle (URL d'outil, keyset, redirection URIs) n'est nécessaire.

Cartes complémentaires sur la même page :

CarteRéglageDéfaut
Tool domainDomaine de la plateforme Glaasterlti.glaaster.com
Icon configurationEnable contextual icons, URL de l'icône, position (gauche / droite / fin du bloc)Activé, droite
Opening modeEmbed, Embed, without blocks, Existing window, New windowNew window (nouvel onglet) depuis 5.3.2

Le mode d'ouverture est un réglage global qui prime sur celui du type d'outil. Sur téléphone/tablette, Glaaster s'ouvre toujours dans la fenêtre existante.

En cas de problème de connexion : FAQ https://support.glaaster.com ou support@glaaster.com.

Configuration minimale​

1. Activer les web services et le protocole REST​

php admin/cli/cfg.php --name=enablewebservices --set=1

Ou via l'interface :

  • Site administration → Advanced features → Enable web services : ✅
  • Site administration → Server → Web services → Manage protocols : activer REST

2. Vérifier le rôle Glaaster API​

Le rôle est créé et maintenu par le plugin (install + upgrades). Capacités accordées :

CapacitéUsage
moodle/course:viewVoir les cours sans inscription
moodle/course:updateRequis par core_course_get_contents
moodle/course:viewhiddencoursesCours cachés
moodle/course:viewhiddensectionsSections cachées
moodle/course:viewhiddenactivitiesActivités cachées
moodle/course:ignoreavailabilityrestrictionsActivités avec restrictions d'accès
mod/resource:viewRessources fichier
mod/folder:viewContenu des dossiers
webservice/rest:useProtocole REST
moodle/cohort:viewCohortes des autres utilisateurs (5.3.4+)

⚠️ 5.3.3 uniquement : moodle/cohort:view n'était pas encore accordée par le plugin. Sans elle, mod_glaaster_get_user_cohorts échoue avec required_capability_exception dès que le Document Service demande les cohortes d'un autre utilisateur. Mettre à jour en 5.3.4+, ou l'ajouter à la main : Site administration → Users → Permissions → Define roles → Glaaster API → autoriser moodle/cohort:view.

Les upgrades réappliquent ces capacités avec écrasement : une capacité de la liste passée manuellement à Prevent/Prohibit repasse à Allow.

Premier lancement​

1. Conteneur Glaaster provisionné automatiquement​

Dès que la connexion (étape 4) aboutit, le plugin crée automatiquement une catégorie et un cours visibles nommés Glaaster, contenant l'unique activité Glaaster du site. Tout utilisateur authentifié y reçoit moodle/course:view et mod/glaaster:view (dans ce cours uniquement), pour lancer Glaaster sans inscription.

Aucune action enseignant n'est requise : pas besoin d'ajouter une activité Glaaster dans les cours.

2. Tester le lancement​

  1. Ouvrir le cours Glaaster et cliquer sur l'activité
  2. ✅ Glaaster s'ouvre selon le mode choisi (nouvel onglet par défaut)

Résultat attendu :

  • Pas d'erreur de signature JWT
  • Connexion automatique (SSO)
  • Nom d'utilisateur et rôle correctement transmis

3. Tester les icônes contextuelles​

  1. Dans n'importe quel cours, ajouter une ressource Fichier ou un Dossier (JPG, PNG, PDF, DOCX, PPTX, ODT, ODP)
  2. Recharger la page du cours
  3. ✅ Une icône Glaaster (« Voir le document de manière adaptée ») apparaît à côté du fichier

Cliquer sur l'icône :

  • Lancement de l'activité Glaaster (view.php avec resource_id, ou file_name/file_path pour un fichier de dossier)
  • Document chargé dans Glaaster

Si l'icône est grisée avec un badge « ? » (« Glaaster is not configured yet »), aucune instance valide n'est trouvée : voir Dépannage.

Vérification de l'installation​

Checklist de vérification​

✅ Plugin installé​

php admin/cli/cfg.php --component=mod_glaaster

Résultat attendu : Affichage des paramètres du plugin (tooldomain, apiuserid, iconsenabled, launchcontainer…)

✅ Web services activés​

php admin/cli/cfg.php --name=enablewebservices

Résultat attendu : 1

✅ Service glaaster_api et fonction mod_glaaster_validate_instance enregistrés​

SELECT id, enabled FROM mdl_external_services WHERE shortname = 'glaaster_api';
SELECT name FROM mdl_external_functions WHERE name = 'mod_glaaster_validate_instance';

Résultat attendu : 1 ligne pour chaque requête

✅ Carte « Glaaster API Setup » entièrement « Ready »​

Rôle, service, utilisateur API et token au statut Ready sur toolconfigure.php.

✅ JWKS endpoint accessible​

curl https://votre-moodle.com/mod/glaaster/certs.php

Résultat attendu : JSON avec clés publiques

{
  "keys": [
    {
      "kty": "RSA",
      "alg": "RS256",
      "kid": "...",
      "n": "...",
      "e": "AQAB"
    }
  ]
}

✅ Icônes contextuelles fonctionnelles​

  1. Ajouter un fichier PDF dans un cours
  2. Vérifier la présence de l'icône Glaaster (active, sans badge « ? »)
  3. Cliquer → Vérifier la redirection vers view.php avec resource_id en paramètre

Dépannage rapide​

Problème : Aucune icône Glaaster​

Solution :

  1. Vérifier Enable contextual icons (carte Icon configuration)
  2. Vérifier que le type de fichier est supporté (JPG, PNG, PDF, DOCX, PPTX, ODT, ODP)
  3. Vérifier la console JavaScript pour erreurs
  4. Purger les caches (voir ci-dessous)

Problème : Icônes grisées avec badge « ? »​

Aucune instance Glaaster valide n'est trouvée pour le Tool domain configuré.

Solution :

  1. Vérifier que la connexion (étape 4) a abouti et que le Tool domain est correct
  2. Vérifier que le cours/l'activité Glaaster existe et n'est pas en cours de suppression : 
    SELECT cm.id, cm.course, cm.visible, cm.deletioninprogress
    FROM mdl_course_modules cm
    JOIN mdl_modules m ON m.id = cm.module
    WHERE m.name = 'glaaster';
  3. Lancer l'upgrade (provisionne rétroactivement le conteneur si nécessaire) puis purger les caches

Problème : Changements non pris en compte après mise à jour​

Toujours lancer, après chaque mise à jour du plugin :

php admin/cli/upgrade.php
php admin/cli/purge_caches.php

L'upgrade enregistre les services web et met à jour le rôle Glaaster API ; la purge recharge le JavaScript, les chaînes de langue et les URLs de lancement en cache. Puis rafraîchir le navigateur (Ctrl+Shift+R).

Problème : Activité Glaaster bloquée en suppression (deletioninprogress = 1)​

Corrigé en 5.3.1 pour les nouvelles suppressions ; les activités déjà bloquées doivent être débloquées manuellement :

SELECT cm.id, cm.course, cm.instance
FROM mdl_course_modules cm
JOIN mdl_modules m ON m.id = cm.module
WHERE m.name = 'glaaster' AND cm.deletioninprogress = 1;

Remettre deletioninprogress à 0 sur ces lignes, purger les caches, puis relancer la suppression depuis la page du cours.

Problème : required_capability_exception sur les cohortes​

mod_glaaster_get_user_cohorts exige moodle/cohort:view (niveau système) depuis 5.3.3. Mettre à jour en 5.3.4+ (accordée automatiquement), ou l'accorder au rôle Glaaster API (voir Configuration minimale).

Problème : Erreur "Invalid JWT signature"​

Causes possibles :

  • URL Moodle incorrecte dans iss claim
  • Clés JWKS non synchronisées
  • Horloge serveur désynchronisée

Solution :

  1. Vérifier l'URL Moodle : 
    php admin/cli/cfg.php --name=wwwroot
  2. Vérifier JWKS endpoint : 
    curl https://votre-moodle.com/mod/glaaster/certs.php
  3. Synchroniser horloge serveur : 
    sudo ntpdate pool.ntp.org

Problème : Web service non disponible​

Solution :

  1. Activer les web services et le protocole REST : 
    php admin/cli/cfg.php --name=enablewebservices --set=1
  2. Upgrade Moodle (enregistre les services) : 
    php admin/cli/upgrade.php
  3. Vérifier l'enregistrement : 
    SELECT * FROM mdl_external_services WHERE shortname = 'glaaster_api';

Problème : Erreur HTTPS requis pour LTI​

Solution (développement) : Utiliser Cloudflare Tunnel pour exposer Moodle local en HTTPS :

# Installer cloudflared
# https://developers.cloudflare.com/cloudflare-one/connections/connect-apps/install-and-setup/

# Créer tunnel
cloudflared tunnel --url http://localhost:8080

Résultat : URL HTTPS temporaire (ex: https://abc123.trycloudflare.com)

Développement (optionnel)​

Installer les dépendances Node.js​

À la racine du dépôt (où se trouvent package.json et Gruntfile.js) :

yarn install

Build des assets​

# Build complet (JavaScript + SCSS)
grunt

# Build AMD uniquement
grunt amd

# Watch mode (rebuild automatique)
grunt watch

Linting​

# JavaScript
grunt eslint

# SCSS/CSS
grunt stylelint

Tests PHPUnit​

# Configuration
export DB_HOST=localhost
export DB_PORT=5432
export DB_USER=postgres
export DB_PASS=postgres
export DB_NAME=moodle_test

# Exécution (depuis la racine Moodle)
vendor/bin/phpunit --testsuite mod_glaaster_testsuite

Tests Behat​

# Configuration Behat
php admin/tool/behat/cli/init.php

# Exécution
vendor/bin/behat --tags=@mod_glaaster

Environnements multiples​

Développement local​

Moodle config (config.php) :

$CFG->debug = DEBUG_DEVELOPER;
$CFG->debugdisplay = 1;
$CFG->cachejs = false;
$CFG->themedesignermode = true;

Commandes utiles :

# Purge caches après changements
php admin/cli/purge_caches.php

# Rebuild des assets
grunt amd

Staging​

Moodle config :

$CFG->debug = DEBUG_NORMAL;
$CFG->debugdisplay = 0;

Déploiement :

# Build assets
grunt

# Upgrade plugin
php admin/cli/upgrade.php

# Purge caches
php admin/cli/purge_caches.php

Production​

Moodle config :

$CFG->debug = 0;
$CFG->debugdisplay = 0;
$CFG->cachejs = true;
$CFG->themedesignermode = false;

Déploiement :

# Backup base de données
mysqldump -u root -p moodle > backup_$(date +%Y%m%d).sql

# Upload nouveau code
rsync -avz --exclude='.git' mod/glaaster/ server:/path/to/moodle/mod/glaaster/

# Upgrade via CLI (maintenance mode)
ssh server "cd /path/to/moodle && php admin/cli/upgrade.php"

# Purge caches
ssh server "cd /path/to/moodle && php admin/cli/purge_caches.php"
