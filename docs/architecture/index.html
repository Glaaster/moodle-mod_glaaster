Architecture du Plugin Glaaster

Vue d'ensemble architecturale​

Le plugin Glaaster (mod_glaaster, fork de mod/lti) suit l'architecture des modules d'activité Moodle, avec des extensions pour l'intégration LTI 1.3 et l'ouverture contextuelle des ressources. Il cible Moodle 4.5 à 5.2 ($plugin->supported = [405, 502]) et PHP 8.1 à 8.4.

Depuis la 5.0, les fonctions lti_glaaster_* sont renommées glaaster_*, les constantes LTI_GLAASTER_* deviennent GLAASTER_* / MOD_GLAASTER_*, et les classes OAuth 1.0 sont déléguées à mod_lti (les fichiers OAuth.php / TrivialStore.php embarqués ont été supprimés).

Cliquer pour agrandir

La synchronisation des notes (AGS / Basic Outcomes) n'existe plus : la table glaaster_submission et les sous-plugins ltiglaasterservice_basicoutcomes / ltiglaasterservice_gradebookservices sont supprimés par db/upgrade.php.

Patterns architecturaux​

1. Pattern MVC Adapté (Moodle)​

Le plugin utilise une variation du pattern MVC spécifique à Moodle :

  • Modèle : Classes dans classes/, accès données via $DB global
  • Vue : Output API ($OUTPUT, renderers de classes/output/), templates Mustache et modules AMD
  • Contrôleur : Fichiers PHP racine (view.php, launch.php, auth.php, etc.)

2. Plugin Architecture (Moodle)​

Cliquer pour agrandir

Les types de sous-plugins sont déclarés dans db/subplugins.json (service/ et source/).

3. Service Layer Pattern​

Les services LTI sont organisés en couches :

service_base (abstract, classes/local/ltiglaasterservice/)
├── memberships
│   ├── contextmemberships (resource)
│   └── linkmemberships (resource)
├── toolsettings
│   ├── systemsettings (resource)
│   ├── contextsettings (resource)
│   └── linksettings (resource)
├── profile      (LTI 2.0)
└── toolproxy    (LTI 2.0)

Chaque service hérite de service_base, implémente get_resources() et expose des ressources REST (resource_base) servies par services.php.

4. Hook System (Moodle 4.4+)​

Cliquer pour agrandir

db/hooks.php n'enregistre que before_footer_html_generation. L'ancien callback mod_glaaster_before_standard_top_of_body_html() et glaaster_extend_navigation_course() ont été supprimés.

5. Construction du JWT​

// Simplifié : glaaster_build_request() prépare les paramètres,
// glaaster_sign_jwt() les convertit en claims puis signe (RS256).
$parms['lti_message_type'] = glaaster_get_jwt_message_type_mapping()[$type];
// basic-lti-launch-request   -> LtiResourceLinkRequest
// ContentItemSelectionRequest -> LtiDeepLinkingRequest
// LtiSubmissionReviewRequest  -> LtiSubmissionReviewRequest
$claimmapping = glaaster_get_jwt_claim_mapping(); // mappings standard + services
$jwt = JWT::encode($payload, $privatekey['key'], 'RS256', $privatekey['kid']);

Composants spécifiques Glaaster​

Instance conteneur auto-provisionnée (5.1+)​

Il n'existe qu'une instance Glaaster par site. glaaster_provision_hidden_instance() la crée dès qu'un type d'outil passe à l'état configuré (glaaster_add_type()), et une étape de db/upgrade.php la provisionne rétroactivement. L'opération est idempotente et encapsulée dans un try/catch pour ne jamais bloquer l'enregistrement de l'outil.

Depuis la 5.2.0, la catégorie (idnumber = glaaster_hidden_category), le cours (nommé Glaaster) et le course module sont visibles. glaaster_grant_container_course_access() accorde au rôle archétype user moodle/course:view et mod/glaaster:view dans le contexte de ce cours uniquement : le lancement fonctionne sans inscription.

L'instance utilisée par les boutons est résolue par glaaster_retrieve_instance_from_tooldomain() (type dont tooldomain = config tooldomain, par défaut lti.glaaster.com, puis premier course module avec deletioninprogress = 0).

Icônes contextuelles (5.1+)​

  • Toujours injectées sur les fichiers supportés (PDF, PNG, JPG, DOCX, PPTX, ODT, ODP), y compris en format Tiles (setupContentObserver).
  • Sans instance valide, l'icône est affichée en état désactivé (.glaaster-icon-disabled, badge « ? », navigation bloquée par un listener de clic, infobulle conservée).
  • Réglage admin mod_glaaster/iconsenabled (défaut : activé) pour masquer toutes les icônes.
  • En mode nouvel onglet effectif, le lien reçoit target="_blank", rel="noopener" et forceview=1 (jamais sur mobile/tablette, qui lancent toujours en fenêtre existante — 5.3.4) (view.php redirige directement vers le lancement) ; jamais sur une icône désactivée.

Mode d'ouverture (5.2+)​

Le réglage site mod_glaaster/launchcontainer (carte « Opening mode » de toolconfigure.php) est lu par glaaster_get_default_launch_container() et prime sur la valeur du type d'outil dans glaaster_get_launch_container(). Options : embarqué avec blocs, embarqué sans blocs, fenêtre existante, nouvel onglet. Défaut depuis 5.3.2 : nouvel onglet (MOD_GLAASTER_LAUNCH_CONTAINER_WINDOW). Sur mobile/tablette, fenêtre existante forcée. L'enregistrement reconstruit le cache des cours (glaaster_get_coursemodule_info() fige le mode dans cached_cm_info). iframe-loader.js n'est chargé que pour les lancements embarqués.

Service Glaaster API​

Service REST pré-déclaré dans db/services.php (shortname glaaster_api, utilisateurs restreints, téléchargement de fichiers autorisé) utilisé par le Document Service : mod_resource_get_resources_by_courses, core_files_get_files, core_course_get_contents, core_group_get_course_user_groups, mod_glaaster_get_user_cohorts.

Le rôle glaasterapi (mod_glaaster_create_api_role() / mod_glaaster_assign_api_role_capabilities() dans db/install.php, idempotent) porte : moodle/course:view, moodle/course:update, moodle/course:viewhiddencourses, moodle/course:viewhiddensections, moodle/course:viewhiddenactivities, moodle/course:ignoreavailabilityrestrictions, mod/resource:view, mod/folder:view, webservice/rest:use et moodle/cohort:view (accordée automatiquement depuis 5.3.4, requise depuis 5.3.3 par get_user_cohorts).

Sécurité de l'architecture​

1. JWT Signature Verification​

Cliquer pour agrandir

Côté plugin, glaaster_verify_with_keyset() valide le JWKS téléchargé (tableau contenant keys) et lève errorkeysetdownloadfailed sinon. Le keyset est mis en cache (db/caches.php, keyset).

2. Web Service Authentication​

// Dans db/services.php
'mod_glaaster_validate_instance' => [
    'classname'     => 'mod_glaaster_external',
    'methodname'    => 'validate_instance',
    'type'          => 'read',
    'ajax'          => true,
    'loginrequired' => false, // Performance : pas d'auth pour la validation
],

Note : validate_instance n'exige pas d'authentification pour des raisons de performance (<500ms), mais ne retourne que {isvalid}. Même choix pour mod_glaaster_check_tool_status (proxy serveur vers /status de l'outil, retourne {active}).

À l'inverse, mod_glaaster_get_user_cohorts (5.3.3+) n'est pas exposé en AJAX : il est appelé uniquement par le Document Service via le token REST Glaaster API. Lire les cohortes d'un autre utilisateur exige moodle/cohort:view (contexte système) ; un utilisateur peut toujours lire les siennes.

2bis. Authentification avant initiation LTI 1.3 (5.3.3+)​

launch.php et contentitem.php appellent require_login() et vérifient les capacités avant de démarrer le flux OIDC. Un visiteur anonyme ne peut plus obtenir l'URL de login de l'outil, son client_id, ni sonder l'existence d'un course module.

2ter. Durcissements complémentaires (5.3.3)​

  • auth.php : redirect_uri (déjà whitelistée et en PARAM_URL) échappée dans le formulaire auto-soumis ; un launch id absent de la session renvoie invalid_request.
  • Enregistrement dynamique : jwks_uri et initiate_login_uri doivent être des URL http(s) valides (invalid_jwks_uri / invalid_initiate_login_uri, HTTP 400).
  • Payload content_items échappé avec s() dans le message errorinvaliddata.
  • request_tool.php : chargements en MUST_EXIST.

3. SQL Injection Prevention​

Toutes les requêtes utilisent des requêtes paramétrées via l'API $DB de Moodle :

// Exemple dans glaaster_retrieve_instance_from_tooldomain() (locallib.php)
$cmexists = $DB->record_exists_sql(
    "SELECT cm.id
     FROM {course_modules} cm
     WHERE cm.course = ?
       AND cm.module = ?
       AND cm.instance = ?
       AND cm.deletioninprogress = 0",
    [$instance->course, $moduleid, $instance->id]
);

Extensibilité​

Ajout d'un nouveau service LTI​

  1. Créer le sous-plugin dans service/monservice/ (avec version.php, lang/)
  2. Hériter de mod_glaaster\local\ltiglaasterservice\service_base
  3. Implémenter get_resources() (et au besoin get_permitted_scopes(), get_jwt_claim_mappings())
  4. Créer les ressources dans service/monservice/classes/local/resources/ (héritant de resource_base)

Ajout d'un nouveau claim JWT​

  1. Ajouter le paramètre dans glaaster_build_request() (locallib.php)
  2. Soit ajouter un mapping dans glaaster_get_jwt_claim_mapping() (claim préfixé IMS), soit le promouvoir en claim racine dans glaaster_sign_jwt() (cas des claims Glaaster)
  3. Mettre à jour le compteur de paramètres dans tests/externallib_test.php

Performance et optimisation​

1. Cache Moodle​

  • Cache applicatif keyset (db/caches.php) pour les clés JWKS des outils
  • Tokens OAuth2 stockés en base (glaaster_access_tokens), purgés par la tâche planifiée clean_access_tokens
  • Infos de course module (cached_cm_info) : purge requise après changement du mode d'ouverture

2. MutationObserver (optimisation DOM)​

Au lieu de polling régulier, un MutationObserver détecte les suppressions d'instances en temps réel et désactive les boutons en place, réduisant la charge serveur.

3. Minification JavaScript​

Les modules AMD sont compilés et minifiés par Grunt :

amd/src/*.js → (Babel + Rollup) → amd/build/*.min.js

Compatibilité multi-versions Moodle​

Il n'y a plus de chargement JavaScript conditionnel selon la version : sur toutes les versions supportées (4.5 à 5.2), le hook before_footer_html_generation charge le module AMD unique mod_glaaster/before_footer. Les seuls écarts de version sont gérés côté tests/CI (ex. champs enableaitools / enabledaiactions de get_ltis_by_courses en 5.1+, config.php sous public/ en 5.x).

Tables de données​

db/install.xml : glaaster, glaaster_tool_proxies, glaaster_types, glaaster_types_config, glaaster_tool_settings, glaaster_access_tokens, glaaster_types_categories, glaaster_coursevisible.
