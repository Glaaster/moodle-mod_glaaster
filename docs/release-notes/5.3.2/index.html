Release Notes — v5.3.2

Changes since v5.3.1

Patch release. One behaviour fix, no new features, no database schema changes, no breaking changes.

Glaaster now opens in a new browser tab by default when no launch mode has been chosen.

🐛 Bug Fixes​

Default launch container is now a new browser tab​

The site-wide "How Glaaster opens" setting (mod_glaaster/launchcontainer) fell back to MOD_GLAASTER_LAUNCH_CONTAINER_EMBED_NO_BLOCKS whenever an administrator had not chosen a mode explicitly. That fallback was inherited from the behaviour that applied before the setting existed — but Glaaster is expected to open in a new tab, so a fresh site got the wrong experience until someone went and set the option by hand.

The fallback now resolves to MOD_GLAASTER_LAUNCH_CONTAINER_WINDOW, applied to all three places it was used:

LocationRole of the fallback
glaaster_get_default_launch_container() in locallib.phpRead path — used when the stored value is missing or not a valid option
toolconfigure.phpWrite path — the guard that sanitises an invalid submitted value before set_config()
registration_helper.phpThe launch container seeded on LTI dynamic registration

Existing sites with the setting already saved are unaffected. The change only moves the fallback: a site where an administrator picked Embed, Embed without blocks or New window keeps exactly that value, because the stored value is still a valid option and the fallback is never reached.

Affected are sites that never touched the setting, and tools registered through dynamic registration from this version onward.

Upgrade Notes​

Standard plugin upgrade — no manual intervention required, no schema change.

php admin/cli/upgrade.php
php admin/cli/purge_caches.php

The cache purge is required: glaaster_get_coursemodule_info() bakes the launch behaviour into cached_cm_info, so existing activities keep opening the old way until the course module cache is rebuilt.

To keep embedded launches, set the mode explicitly rather than relying on the fallback — Site administration → Plugins → Activity modules → Glaaster → How Glaaster opens → Embed without blocks. Once saved, the value is stored and the changed fallback never applies.

Tools already registered through dynamic registration keep their existing launch container; only new registrations are seeded with the new default.
