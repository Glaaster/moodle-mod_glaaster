Release Notes — v5.2.1

Changes since v5.2.0

Patch release. No new features, no database schema changes, no breaking changes. Two fixes: one permission grant for the Glaaster API role, one CI reliability fix.

🐛 Bug Fixes​

Glaaster API role now ignores activity availability restrictions​

The "Glaaster API" role already carried the capabilities needed to reach hidden courses, hidden sections and hidden activities. It did not carry moodle/course:ignoreavailabilityrestrictions.

As a result, the Document Service could not reach resources whose activity carried an availability restriction — a date window, a grade condition, a group or grouping condition. Such documents were invisible to Glaaster even though the role was otherwise fully privileged, and the failure was silent: the file simply did not appear.

  • moodle/course:ignoreavailabilityrestrictions is now granted to the role on fresh installs (added to mod_glaaster_assign_api_role_capabilities()).
  • A new upgrade step grants it on existing installs. The role-provisioning function is idempotent, so the step only adds the missing capability and leaves everything else untouched.

The role's full capability set is now:

CapabilityPurpose
moodle/course:viewView courses without enrolment
moodle/course:updateRequired by core_course_get_contents
moodle/course:viewhiddencoursesReach resources in hidden courses
moodle/course:viewhiddensectionsReach resources in hidden sections
moodle/course:viewhiddenactivitiesReach hidden resource activities
moodle/course:ignoreavailabilityrestrictionsNew — reach restricted activities
mod/resource:viewView file resources
mod/folder:viewList folder contents
webservice/rest:useUse the REST protocol

Upgrade steps consolidated and renumbered​

Three separate upgrade blocks all did the same thing — require install.php and call mod_glaaster_create_api_role() — across versions 2026090900, 2026090901 and 2026090902. The 2026090900 block has been folded into 2026090901, and the folder capability block renumbered to 2026091000 to carry the new grant.

Behaviour is unchanged for any site upgrading from 5.2.0 or earlier: the role-provisioning call is idempotent and re-runs harmlessly, so collapsing the blocks loses nothing.

👷 CI​

Unit tests no longer silently pass​

Two problems let a red test suite ship a release:

  • The test job carried continue-on-error: true, so failures never failed the job.
  • The release job was gated on !cancelled() rather than on the test result, so semantic-release ran and tagged even when tests had failed.

Both are fixed: continue-on-error is removed, and the release gate is now needs.test.result == 'success'. A failing test suite now blocks the release.

External-file tests skipped instead of failing​

Several advanced_testcase tests require Moodle's external fixture server, which is not reachable from the CI runner — so they failed for environmental reasons rather than real defects.

A new CI step defines TEST_EXTERNAL_FILES_HTTP_URL and TEST_EXTERNAL_FILES_HTTPS_URL as empty PHP constants in Moodle's config.php, which makes Moodle skip those tests rather than fail them. The step locates config.php at either moodle/config.php or moodle/public/config.php (Moodle 5.x moved it beside public/), and fails loudly if the file or its // Extra config. marker is missing rather than patching silently.

Upgrade Notes​

Standard plugin upgrade — no manual intervention required.

php admin/cli/upgrade.php

The upgrade step re-provisions the "Glaaster API" role and adds the new capability. No cache purge is needed: no JavaScript, SCSS or language strings changed in this release.

If the role was customised manually, note that assign_capability() is called with $overwrite = true for every capability in the list. Any of the nine capabilities above that had been set to Prevent or Prohibit by hand will be reset to Allow. Capabilities outside that list are left alone.
