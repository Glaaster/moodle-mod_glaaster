Release Notes — v5.0.0

Changes since v4.5.3 (2026-06-03)

⚠️ Breaking Changes​

  • Release channel renamed — the main branch now publishes under the semantic-release channel 5.0 instead of main. Downstream tooling that pinned to the main dist-tag/channel must switch to 5.0.
  • $plugin->supported range extended and re-based — version.php now declares [405, 502] (previously [405, 405]). This is a support-matrix change, not a code-breaking one, but it changes which Moodle versions the plugin advertises as compatible.

Compatibility​

  • Added support for Moodle 5.0, 5.1, and 5.2 ($plugin->supported = [405, 502]). CI now runs the full test matrix (PHPUnit, Behat, PHPCS) against MOODLE_500_STABLE, MOODLE_501_STABLE, and MOODLE_502_STABLE in addition to MOODLE_405_STABLE.
  • Added PHP 8.4 support — required for Moodle 5.2; PHP 8.1–8.3 remain supported for Moodle 4.5–5.1.
  • Bumped the CI Postgres service image from 15 to 16.
  • No plugin API changes were required for 5.0/5.1 compatibility. One test-only adjustment was needed for Moodle 5.1+, which adds enableaitools and enabledaiactions fields to the get_ltis_by_courses external function output (mod_glaaster has no matching columns, so both are always null).

Bug Fixes​

Robustness​

  • Hardened glaaster_verify_with_keyset() (locallib.php) — the JWKS refetch/refresh path now validates that the downloaded keyset actually decoded to an array containing a keys entry before use, and throws a clear errorkeysetdownloadfailed error instead of failing further downstream with an obscure error when the JWKS endpoint is unreachable or returns malformed data.
  • fix: remove the check on system@glaaster.com — removed a hard-coded email check that no longer reflected actual usage.
  • fix: button disable for send email — corrected the disabled state of the send-email button.

Security & Code Quality​

  • #3 Fix direct superglobal access — replaced raw $_GET/$_POST/$_SERVER with Moodle required_param() / optional_param() equivalents
  • #7 Fix PARAM_RAW security risk — tightened parameter types to appropriate PARAM_* constants
  • #8 Fix inadequate capability checking — added proper require_capability() guards
  • #9 Fix direct config_plugins table access — replaced with get_config() / set_config() API calls
  • #10 Fix Privacy API class missing personal data — extended provider to cover all stored personal data fields

Standards Compliance​

  • #4 Add missing plugin license file (LICENSE)
  • #5 Implement missing Activity Module backup/restore support
  • #11 Fix Frankenstyle constants violation — renamed LTI_GLAASTER_* constants to GLAASTER_*
  • #12 Update JS implementation to ES6 modules — converted legacy scripts to proper AMD/ES6 format
  • #13 Fix hard-coded language strings — moved all user-facing strings to lang/en/glaaster.php
  • #14 Fix risky global $SESSION usage — scoped session access via Moodle API
  • #15 Transition to Templates, Output API, and AMD JavaScript Modules — full adoption of Moodle output layer ($OUTPUT, Mustache templates, AMD)
  • #16 Add missing file boilerplate headers — all PHP files now include required GPL header block
  • #17 Add missing language string definitions — resolved undefined string keys

Refactoring​

  • Namespace & OAuth delegation — removed bundled OAuth.php / TrivialStore.php (1 152 lines) and delegated OAuth classes to mod_lti. Renamed 88 functions (lti_glaaster_* → glaaster_*) and 29 constants across 52 files. Resolves Moodle namespace collision blocker (moodledev.io checklist)

CI / Release Tooling​

  • semantic-release now uses the conventionalcommits preset for commit analysis (was the default angular preset).
  • Updated README.md badges and requirements table to reflect the Moodle 4.5–5.2 / PHP 8.1–8.4 support matrix.

Internal​

  • Lint fixes following ES6/AMD migration (no functional change)
