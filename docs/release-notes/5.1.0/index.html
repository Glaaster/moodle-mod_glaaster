Release Notes — v5.1.0

Changes since v5.0.0

✨ Features​

Contextual icons always visible, with a disabled state​

Previously, the contextual Glaaster button/icon on supported documents (JPG, PNG, PDF, DOCX, PPTX, ODT, ODP) was only injected when a valid, non-deleted Glaaster instance could be resolved on the site. If that check failed for any reason, no icon appeared anywhere.

  • Icons are now always injected on supported documents, regardless of instance status.
  • When no valid instance is configured (or it becomes invalid — e.g. deleted mid-session), the icon stays visible but switches to a disabled state: greyed out, non-clickable (navigation is blocked in JS rather than via pointer-events: none, so hover/focus keep working), with a small "?" badge in the top-right corner and a tooltip explaining the plugin isn't configured yet.
  • The real-time deletion watcher (MutationObserver) now disables existing buttons in place instead of removing them when an instance disappears from the DOM.

New admin setting: disable contextual icons globally​

  • Added a global "Enable contextual icons" checkbox in the icon configuration card (Site administration → Plugins → Activity modules → Glaaster). When unchecked, no Glaaster icon is rendered anywhere on the site, regardless of instance status.
  • Enabled by default on both new and existing installations.

Auto-provisioned hidden instance — zero teacher action required​

Contextual buttons need a real Glaaster activity instance to build working launch links. Previously this instance only ever existed if a teacher manually added the "Glaaster" activity to a course — meaning icons stayed disabled after admin setup alone.

  • The admin "Connect to Glaaster" step (LTI Advantage dynamic registration) now automatically provisions a single hidden Glaaster instance (hidden category + hidden course + course module) the moment a tool type becomes connected. No teacher action is required — icons activate site-wide as soon as the admin finishes configuration.
  • Provisioning is idempotent and defensive: wrapped in try/catch so a provisioning failure never breaks LTI tool registration; safe to re-run.
  • A retroactive upgrade step provisions the hidden instance for sites that had already connected a tool type before this change shipped.

🐛 Bug Fixes​

  • Fixed the disabled-icon tooltip not appearing: the previous approach (pointer-events: none) also blocked hover, so the title attribute never fired. Links now keep href="#" and block navigation via a click listener instead.
  • fix: Depracted callback before_standard_top_of_body_html — removed the dead legacy mod_glaaster_before_standard_top_of_body_html() callback (superseded by the before_footer_html_generation hook; unreachable on supported Moodle versions).

🔧 Code Quality​

  • Fixed two @babel/no-unused-expressions lint errors in before_footer.js (ternary-used-as-statement replaced with if/else; no behavior change, minified output unchanged).

Files Changed​

  • mod/glaaster/locallib.php — new glaaster_provision_hidden_instance(), updated mod_glaaster_get_js_config() (instanceValid, iconsEnabled), hook in glaaster_add_type().
  • mod/glaaster/amd/src/before_footer.js — always-inject logic, disabled-state rendering, click-blocking instead of pointer-events: none.
  • mod/glaaster/styles.css — .glaaster-icon-disabled (greyed out + "?" badge).
  • mod/glaaster/toolconfigure.php — "Enable contextual icons" checkbox + handler.
  • mod/glaaster/lang/en/glaaster.php, lang/fr/glaaster.php — new strings (iconsenabled, iconsenabled_desc, not_configured_tooltip).
  • mod/glaaster/db/upgrade.php — retroactive hidden-instance provisioning step.
  • mod/glaaster/lib.php — removed deprecated before_standard_top_of_body_html callback.
  • mod/glaaster/version.php — version bump.
