Release Notes — v5.3.3

Changes since v5.3.2

Security patch release. Addresses the external security review reported in GitHub issues #21 to #29. No new features, no database schema changes.

One behaviour change to check before upgrading: the account used by the Glaaster Document Service must hold moodle/cohort:view at system level (see Upgrade Notes).

🔒 Security Fixes​

Cohort memberships no longer readable for any user — #21​

mod_glaaster_get_user_cohorts returned the cohorts of any userid to any authenticated caller, including through AJAX from a browser session (IDOR).

  • Reading another user's cohorts now requires moodle/cohort:view in the system context. A user can still read their own cohorts.
  • The function is no longer exposed to AJAX ('ajax' => true removed). It was only used by the Document Service through the Glaaster API token; no JavaScript called it.
  • db/services.php now declares 'capabilities' => 'moodle/cohort:view'.

Authentication before LTI 1.3 login initiation — #24​

launch.php and contentitem.php started the LTI 1.3 OIDC flow before calling require_login(). An anonymous visitor could trigger the auto-submitted login form and learn the tool's login initiation URL, its client_id, and whether a course module exists.

require_login() and the capability checks (mod/glaaster:view for launches; moodle/course:manageactivities + mod/glaaster:addcoursetool for content selection) now run first. Logged-in users see no difference.

Content items payload escaped in error message — #28​

The raw PARAM_RAW value of content_items stays, because it is JSON-LD that any Moodle filter would corrupt. Signature, login, sesskey and capabilities are still checked before it is used. While reviewing this, we found that glaaster_tool_configuration_from_content_item() put the raw payload into the errorinvaliddata message, which is rendered as HTML by notification::error(). The value is now escaped with s().

Dynamic registration URIs validated — #27​

jwks_uri and initiate_login_uri from a dynamic registration payload are now required to be well-formed http(s) URLs (PARAM_URL). Other schemes (file://, gopher://…) or malformed values are rejected with invalid_jwks_uri / invalid_initiate_login_uri (HTTP 400). Outgoing JWKS fetches still go through Moodle's curl security helper (curlsecurityblockedhosts).

Hardening in auth.php — #22, #26​

  • redirect_uri is now HTML-escaped in the auto-submit form. It was already whitelisted against the tool's registered redirect URIs and cleaned with PARAM_URL, so this is defense in depth.
  • A launch id missing from the session now returns invalid_request instead of raising PHP warnings.

🐛 Bug Fixes​

Invalid HMAC algorithm name — #23​

registration_helper::sign() called hash_hmac('sha-256', …). PHP only knows sha256, so on PHP 8 the call throws a ValueError. The method is not called anywhere in the plugin today, so this had no runtime impact. Fixed to sha256.

Fatal error on unknown instance in request_tool.php — #25​

An instanceid matching no record led to a property access on false (PHP fatal error). Both lookups now use MUST_EXIST and fail with a standard Moodle error.

Not changed​

#29 (distinct LTI error codes in auth.php) is not a vulnerability. These codes are required by OpenID Connect Core §3.1.2.6 and the 1EdTech Security Framework, and they are only returned to the tool's registered redirect_uri.

Upgrade Notes​

Before upgrading, give the Document Service account moodle/cohort:view at system level. Without it, cohort lookups for other users will fail with required_capability_exception:

Site administration → Users → Permissions → Define roles → role assigned to the Glaaster API token user → allow moodle/cohort:view (system context).

Then run the standard upgrade. It is required so Moodle picks up the changed db/services.php definition:

php admin/cli/upgrade.php
php admin/cli/purge_caches.php

No other manual step. Tools registered through dynamic registration before this version keep their existing configuration; the new URI checks apply only to new registrations.
