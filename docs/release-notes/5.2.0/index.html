Release Notes — v5.2.0

Changes since v5.1.1

✨ Features​

New admin setting: opening mode​

A new "Opening mode" card was added to the Glaaster configuration page (Site administration → Plugins → Activity modules → Glaaster). It lets the administrator decide, site-wide, how Glaaster is displayed:

  • Embedded, with blocks — shown in a frame inside the Moodle page, surrounding blocks kept.
  • Embedded, without blocks — shown in a frame inside the Moodle page, blocks hidden. Recommended, and the default (this is the behaviour that applied before the setting existed).
  • Existing window — takes over the whole page; the Moodle header and navigation are hidden.
  • New tab — opens in a new browser tab, Moodle stays open behind it.

Each option is a radio button with its own explanation. On phones and tablets Glaaster always opens in the existing window, whatever the setting says, to make the best use of the screen.

Unlike core mod_lti, the site-wide setting takes precedence over the tool type value. Tool types are seeded with a concrete launch container when they are registered, so honouring them would make the administrator's choice unreachable; the per-activity value is likewise always DEFAULT for Glaaster instances. The site setting is therefore the single place where the opening mode is decided.

Saving the setting rebuilds every course cache — glaaster_get_coursemodule_info() bakes the launch behaviour into cached_cm_info, so without the rebuild activity links would keep the previous opening mode.

Contextual buttons honour the new-tab mode​

When "New tab" is the configured opening mode, contextual buttons now open the tool in a single step:

  • The injected <a> gets target="_blank" and rel="noopener" (the latter stops the opened tab from reaching back through window.opener).
  • The URL carries forceview=1, and view.php redirects straight to the launch instead of rendering the "opened in a new window" interstitial — previously the user landed on an intermediate page and had to click a second link, which also opened yet another tab.
  • Disabled icons never get target/rel, including when the deletion watcher flips a previously enabled link.

🐛 Bug Fixes​

Container course and activity are now visible​

The auto-provisioned Glaaster container was created hidden (hidden category, hidden course, hidden activity), which made the single site-wide Glaaster activity unreachable for normal users. Now:

  • The container category, course and course module are all created visible, and the course is named Glaaster instead of Glaaster (hidden container).
  • Every authenticated user is granted moodle/course:view and mod/glaaster:view in the container course context only (via the user archetype role), so LTI launches work without enrolment while every other course is left untouched.
  • A retroactive upgrade step un-hides the category, course and activity on existing installs, renames the course, grants the access, and rebuilds the course cache.

Glaaster API role can reach hidden and folder content​

The "Glaaster API" role was missing capabilities the Document Service needs. Added:

  • mod/folder:view — without it the Document Service cannot list files inside folder activities.
  • moodle/course:viewhiddencourses, moodle/course:viewhiddensections, moodle/course:viewhiddenactivities — without them resources sitting in hidden courses, sections or activities are unreachable.

Upgrade steps re-run the role creation so existing installs pick the new capabilities up.

Loader no longer breaks non-embedded launches​

iframe-loader.js assumed #contentframe and div[role='main'] always exist, and threw on new-window / existing-window launches. It now bails out early when the tool is not embedded, and view.php only loads the script for embedded launches.

Removed useless course navigation menu​

Dropped the glaaster_extend_navigation_course() callback, which added an "LTI External tools" link to the course settings navigation pointing at coursetools.php. Not relevant to the Glaaster workflow.

🔧 Internal / CI​

  • PHPUnit: external test files disabled. The CI workflow now defines TEST_EXTERNAL_FILES_HTTP_URL / TEST_EXTERNAL_FILES_HTTPS_URL as empty PHP constants in Moodle's config.php (locating it at either moodle/config.php or moodle/public/config.php depending on the branch), so advanced_testcase skips every test that requires Moodle's external fixture server — unreachable from the runner.
  • CI is no longer allowed to be green while failing. Removed continue-on-error: true from the test job, and the Semantic Release job now requires needs.test.result == 'success' instead of !cancelled().

Files Changed​

  • mod/glaaster/locallib.php — new glaaster_get_launch_container_options(), glaaster_get_default_launch_container(), glaaster_grant_container_course_access(); glaaster_get_launch_container() now reads the site setting only; visible container provisioning; openInNewWindow added to mod_glaaster_get_js_config().
  • mod/glaaster/toolconfigure.php — new "Opening mode" card + savelaunchsettings handler (with rebuild_course_cache).
  • mod/glaaster/view.php — forceview redirects straight to the launch in new-window mode; iframe-loader.js only loaded for embedded launches.
  • mod/glaaster/amd/src/before_footer.js — target="_blank" / rel="noopener" and forceview=1 in new-window mode; disabled icons stripped of target/rel.
  • mod/glaaster/assets/js/iframe-loader.js — guards for missing #contentframe / div[role='main'] and #loader.
  • mod/glaaster/db/install.php — mod/folder:view and the three viewhidden* capabilities added to the Glaaster API role.
  • mod/glaaster/db/upgrade.php — three upgrade steps (2026090900, 2026090901, 2026090902): API role capabilities, visible container + access grant, mod/folder:view.
  • mod/glaaster/lib.php — removed glaaster_extend_navigation_course().
  • mod/glaaster/lang/en/glaaster.php, lang/fr/glaaster.php — new opening-mode strings (launchsettings, launchcontainer_setting, launchcontainer_setting_desc, and one *_desc per option).
  • .github/workflows/ci.yml — external test files disabled; continue-on-error removed; release gated on test success.
  • mod/glaaster/version.php — version bump (2026090906).
