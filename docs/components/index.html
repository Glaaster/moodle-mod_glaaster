Composants et Modules

Ce document détaille chaque module et service majeur du plugin Glaaster (version 5.3.x).

Rappel 5.0.0 : les fonctions lti_glaaster_* ont été renommées glaaster_*, les constantes LTI_GLAASTER_* → GLAASTER_* / MOD_GLAASTER_*. Les fichiers embarqués OAuth.php / TrivialStore.php ont été supprimés : les classes OAuth 1.0 sont déléguées à mod_lti.

Module Principal : mod_glaaster​

Nom​

mod_glaaster - Module d'activité Moodle

Description​

Module d'activité Moodle permettant l'intégration de l'outil LTI 1.3 Glaaster, avec des personnalisations (boutons contextuels, transmission de ressources via JWT, instance unique auto-provisionnée, mode d'ouverture global).

Responsabilités​

  • Gestion du cycle de vie des activités (création, modification, suppression)
  • Génération et validation de JWT LTI 1.3
  • Auto-provisionnement de l'instance « conteneur » unique du site
  • Injection du module AMD des boutons contextuels
  • Exposition de web services (AJAX et REST Glaaster API)
  • Gestion OAuth2 et tokens d'accès

Dépendances entrantes​

  • Moodle Core (API d'activités, base de données, cache, hooks)
  • Subplugins ltiglaasterservice (memberships, profile, toolproxy, toolsettings)

Dépendances sortantes​

  • Outil LTI externe (lti.glaaster.com, config mod_glaaster/tooldomain)
  • mod_lti (classes OAuth 1.0)
  • Base de données et système de cache Moodle

La synchronisation des notes (AGS / Basic Outcomes) a été supprimée : la table glaaster_submission et les subplugins ltiglaasterservice_basicoutcomes / ltiglaasterservice_gradebookservices sont retirés par db/upgrade.php.

Composant : Instance conteneur auto-provisionnée (5.1+)​

Description​

Les boutons contextuels ont besoin d'une vraie instance Glaaster pour construire leurs liens. Il n'existe qu'une seule instance par site, créée automatiquement dès qu'un type d'outil est connecté (« Connect to Glaaster », enregistrement dynamique) — aucune action enseignant.

Fonctionnement​

  • glaaster_add_type() appelle glaaster_provision_hidden_instance($typeid) (dans un try/catch : un échec n'empêche jamais l'enregistrement de l'outil).
  • Crée si besoin la catégorie glaaster_hidden_category, le cours Glaaster (idnumber = glaaster_hidden_container) et le module de cours — tous visibles depuis 5.2.0.
  • glaaster_grant_container_course_access($courseid) accorde moodle/course:view et mod/glaaster:view au rôle d'archétype user dans le contexte du cours conteneur uniquement : lancement sans inscription.
  • Idempotent (retourne l'instance existante pour ce typeid). Une étape de db/upgrade.php provisionne rétroactivement les sites déjà connectés.

Composant : Mode d'ouverture global (5.2+)​

Description​

Réglage site mod_glaaster/launchcontainer, carte « Opening mode » de toolconfigure.php (handler savelaunchsettings, qui reconstruit le cache de tous les cours car glaaster_get_coursemodule_info() fige le comportement dans cached_cm_info).

Service : LTI OpenID Connect​

Nom​

ltiopenid (namespace mod_glaaster\local\ltiopenid)

Description​

Implémentation LTI 1.3 avec OAuth2 / OpenID Connect : gestion des clés et enregistrement dynamique LTI Advantage.

Responsabilités​

  • Publication des clés JWKS de la plateforme
  • Enregistrement dynamique d'outils LTI 1.3 (payload ↔ configuration)
  • Validation du token d'enregistrement

Dépendances entrantes​

  • locallib.php (fonctions de launch), certs.php, openid-registration.php
  • Outils LTI externes (pour enregistrement)

Dépendances sortantes​

  • Bibliothèque firebase/php-jwt
  • OpenSSL (PHP)

Diagramme de classes​

Cliquer pour agrandir

Validation (5.3.3+) : jwks_uri et initiate_login_uri du payload d'enregistrement dynamique doivent être des URL http(s) valides, sinon registration_exception (invalid_jwks_uri / invalid_initiate_login_uri, HTTP 400). sign() utilise hash_hmac('sha256', …) (ancien 'sha-256' invalide en PHP 8). Depuis 5.3.2, l'enregistrement initialise le type avec MOD_GLAASTER_LAUNCH_CONTAINER_WINDOW.

Fichiers sources​

  • classes/local/ltiopenid/jwks_helper.php
  • classes/local/ltiopenid/registration_helper.php
  • classes/local/ltiopenid/registration_exception.php

Module JavaScript : Boutons Contextuels​

Nom​

mod_glaaster/before_footer (module AMD, amd/src/before_footer.js)

Description​

Module chargé par le hook before_footer_html_generation avec la configuration retournée par mod_glaaster_get_js_config(). Détecte les fichiers supportés et injecte les boutons Glaaster contextuels (formats de cours standard et Tiles).

Responsabilités​

  • Détection des ressources (icône f/*) et fichiers de dossiers (extension)
  • Injection systématique des boutons (5.1+) si iconsEnabled
  • État désactivé si pas d'instance valide : classe .glaaster-icon-disabled (grisé + badge « ? », tooltip not_configured_tooltip), navigation bloquée par un listener click (pas pointer-events: none)
  • Mode nouvel onglet : target="_blank", rel="noopener", forceview=1 (jamais sur un bouton désactivé)
  • setupContentObserver : MutationObserver pour le contenu dynamique (Tiles)
  • setupDeletionWatcher : MutationObserver sur la suppression d'une activité Glaaster → AJAX mod_glaaster_validate_instance → désactive les boutons (ne les supprime plus)

Configuration reçue (mod_glaaster_get_js_config())​

instanceId, instanceValid, iconsEnabled, webservicesEnabled, webserviceConfigured, debugEnabled, iconUrl, iconPosition (left / right / blockend), openInNewWindow.

Méthodes clés​

validate_instance(instanceid)​

Description : Valide qu'une instance Glaaster existe et n'est pas en cours de suppression.

Retour : {"isvalid": true|false}

Logique : instance présente dans {glaaster}, cours existant, module de cours avec deletioninprogress = 0. Sans authentification (latence temps réel) ; ne révèle aucune donnée sensible.

get_user_cohorts(userid) (5.3.3+)​

external/get_user_cohorts.php

Description : Retourne les cohortes d'un utilisateur. Utilisé par le Document Service via le token REST Glaaster API (plus exposé en AJAX).

Contrôle d'accès :

  • userid = utilisateur courant → autorisé
  • userid ≠ utilisateur courant → moodle/cohort:view en contexte système, sinon required_capability_exception

Composant : Rôle « Glaaster API » (5.2+)​

Description​

Rôle système (shortname = glaasterapi) destiné à l'utilisateur du token du Document Service. Créé par mod_glaaster_create_api_role() (idempotent) à l'installation et rejoué par les étapes d'upgrade ; capacités posées par mod_glaaster_assign_api_role_capabilities($roleid) (assign_capability(..., true) : écrase toute surcharge manuelle de ces capacités).

Capacités​

moodle/course:view, moodle/course:update (requis par core_course_get_contents), moodle/course:viewhiddencourses, moodle/course:viewhiddensections, moodle/course:viewhiddenactivities, moodle/course:ignoreavailabilityrestrictions (5.2.1), mod/resource:view, mod/folder:view, webservice/rest:use, moodle/cohort:view (5.3.4, requise par get_user_cohorts depuis 5.3.3).

Fichiers sources​

  • db/install.php

Composant : Configuration des icônes (5.1+)​

Carte de configuration dans toolconfigure.php :

  • mod_glaaster/iconsenabled — active/désactive globalement les icônes (défaut : activé)
  • mod_glaaster/iconurl — icône personnalisée (défaut pix/icon.svg)
  • mod_glaaster/iconposition — left, right (défaut) ou blockend

Fichiers sources​
