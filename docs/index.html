Documentation du Plugin Glaaster LTI pour Moodle

Vue d'ensemble​

Le plugin Glaaster Activity est une activité LTI 1.3/Advantage pour Moodle, dérivé du module principal mod/lti (MOODLE_405_STABLE). Il permet l'intégration d'outils externes Glaaster dans les cours Moodle avec des modifications JWT personnalisées et une expérience utilisateur améliorée pour les ressources.

Stack technique​

  • Backend: PHP 8.1 – 8.4 (8.3+ requis pour Moodle 5.2)
  • Base de données: PostgreSQL, MariaDB/MySQL (compatibilité Moodle)
  • Frontend: JavaScript (AMD modules), SCSS
  • Build: Grunt, Babel 7.x, Rollup
  • Sécurité: JWT avec firebase/php-jwt, OAuth2, OpenID Connect
  • Standards: LTI 1.3, LTI Advantage (AGS, NRPS, Deep Linking)

Fonctionnalités principales​

  1. Intégration LTI 1.3 complète

    • Authentification OpenID Connect (auth.php) + tokens OAuth2 (token.php)
    • Génération et validation JWT (clés publiées via certs.php)
    • Services LTI Advantage : NRPS (memberships), profile, toolproxy, toolsettings
    • Enregistrement dynamique (« Connect to Glaaster ») avec validation des URI (5.3.3)
    • La synchronisation des notes (AGS / basicoutcomes) a été supprimée.

  2. Boutons contextuels

    • Détection automatique des types de fichiers supportés (JPG, PNG, PDF, DOCX, PPTX, ODT, ODP)
    • Icônes toujours injectées ; état désactivé (grisé + badge « ? ») si aucune instance valide (5.1)
    • Réglage admin global pour activer/désactiver les icônes (5.1)
    • Support des dossiers et sous-dossiers, formats de cours standard et Tiles

  3. Zéro action enseignant

    • Cours conteneur « Glaaster » + activité provisionnés automatiquement à la connexion (5.1), visibles et accessibles à tous les utilisateurs authentifiés (5.2)

  4. Mode d'ouverture configurable (5.2)

    • Intégré avec/sans blocs, fenêtre existante, nouvel onglet (défaut depuis 5.3.2)
    • Réglage site prioritaire sur le type d'outil ; mobile toujours en fenêtre existante

  5. Personnalisations JWT

    • Claims resource_id ou file_name / file_path (Base64) pour ressources et dossiers
    • redirect (route front optionnelle), activity_cmid, plugin_release, plugin_version (5.3)

  6. Intégration Document Service

    • Service REST pré-configuré glaaster_api + rôle « Glaaster API » créés à l'installation
    • Accès aux contenus cachés, dossiers et activités restreintes (5.2 / 5.2.1)
    • mod_glaaster_get_user_cohorts (exige moodle/cohort:view depuis 5.3.3, accordée au rôle depuis 5.3.4)

  7. Conformité Moodle (5.0)

    • Backup/restore, Privacy API, Output API + Mustache, modules AMD/ES6, chaînes traduites (en/fr), préfixe glaaster_* sans collision de namespace, OAuth délégué à mod_lti
