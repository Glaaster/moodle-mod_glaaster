Flux de Données et Diagrammes de Séquence

Ce document décrit les flux critiques du plugin Glaaster (mod_glaaster, version 5.3.x) avec des diagrammes de séquence. Les étapes côté Glaaster (Reader App, Document Service) sont indicatives : elles ne font pas partie du plugin.

Depuis 5.0, toutes les fonctions lti_glaaster_* sont renommées glaaster_*. La synchronisation des notes (AGS / Basic Outcomes) a été supprimée : table glaaster_submission et sous-plugins gradebookservices / basicoutcomes retirés (db/upgrade.php). Aucun flux de notes n'existe plus.

Flux 1 : Lancement LTI 1.3 avec Ressource​

Description​

Du clic sur l'icône Glaaster d'une ressource jusqu'à l'affichage du document dans le Reader App, avec l'aller-retour OIDC complet (login initiation → auth → id_token).

Diagramme de séquence​

Cliquer pour agrandir

Points d'entrée​

  • Icône contextuelle : view.php?l={instanceid}&course_module_id={resource_cmid} (+ forceview=1 en mode nouvel onglet)
  • Lien activité : view.php?id={cmid}[&redirect={cible}]

Flux 3 : Mode d'ouverture (launch container)​

Description​

Depuis 5.2, le réglage site « Mode d'ouverture » (mod_glaaster/launchcontainer) décide seul de l'affichage ; il prime sur la valeur du type d'outil et de l'activité. Défaut depuis 5.3.2 : nouvel onglet (MOD_GLAASTER_LAUNCH_CONTAINER_WINDOW).

Cliquer pour agrandir
  • Mobile / tablette : toujours fenêtre existante ; depuis 5.3.4 les icônes n'y portent jamais forceview=1 (sinon view.php sautait la redirection et affichait l'iframe).
  • En mode nouvel onglet, les icônes contextuelles portent target="_blank", rel="noopener" et forceview=1 : view.php redirige directement vers launch.php (un seul clic, un seul onglet).
  • iframe-loader.js n'est chargé que pour les lancements intégrés.
  • L'enregistrement du réglage reconstruit le cache de tous les cours (glaaster_get_coursemodule_info()).

Flux 4 : Injection des Boutons Contextuels​

Description​

Détection des fichiers supportés sur une page et injection des icônes Glaaster. Depuis 5.1, les icônes sont toujours injectées ; sans instance valide elles sont affichées désactivées.

Diagramme de séquence​

Flux 5 : Validation d'Instance en Temps Réel​

Description​

Quand l'activité Glaaster disparaît du DOM (suppression dans le cours), les icônes sont revalidées et désactivées sur place (elles ne sont plus retirées depuis 5.1).

Diagramme de séquence​

Cliquer pour agrandir

Déclencheurs et performance​

  • Déclencheur : retrait DOM d'une activité Glaaster (pas de polling)
  • Latence : < 500 ms (détection MutationObserver + un appel AJAX sans authentification)

Flux 6 : Enregistrement Dynamique LTI 1.3 et Provisioning du Conteneur​

Description​

« Connecter à Glaaster » (LTI Advantage Dynamic Registration) crée le type d'outil puis provisionne automatiquement l'unique instance Glaaster du site (5.1+, visible depuis 5.2).

Diagramme de séquence​

Cliquer pour agrandir

Exemple de payload envoyé par l'outil​

{
  "application_type": "web",
  "response_types": ["id_token"],
  "grant_types": ["implicit", "client_credentials"],
  "client_name": "Glaaster",
  "initiate_login_uri": "https://lti.glaaster.com/lti/login",
  "redirect_uris": ["https://lti.glaaster.com/lti/launch"],
  "jwks_uri": "https://lti.glaaster.com/.well-known/jwks.json",
  "token_endpoint_auth_method": "private_key_jwt",
  "scope": "https://purl.imsglobal.org/spec/lti-nrps/scope/contextmembership.readonly",
  "https://purl.imsglobal.org/spec/lti-tool-configuration": {
    "domain": "lti.glaaster.com",
    "target_link_uri": "https://lti.glaaster.com/lti/launch",
    "messages": [
      {"type": "LtiDeepLinkingRequest", "target_link_uri": "https://lti.glaaster.com/lti/deeplink"}
    ]
  }
}

La réponse de Moodle n'accorde que les scopes NRPS et Tool Settings ; aucun scope AGS n'est renvoyé (synchronisation des notes supprimée).

Flux 7 : Appels du Document Service (REST glaaster_api)​

Description​

Le Document Service récupère les fichiers via le service externe pré-construit Glaaster API (shortname glaaster_api, utilisateurs restreints, downloadfiles = 1).

Cliquer pour agrandir

Capacités du rôle « Glaaster API » : moodle/course:view, moodle/course:update, moodle/course:viewhiddencourses, moodle/course:viewhiddensections, moodle/course:viewhiddenactivities, moodle/course:ignoreavailabilityrestrictions (5.2.1), mod/resource:view, mod/folder:view (5.2), webservice/rest:use, moodle/cohort:view (accordée automatiquement depuis 5.3.4).

Performance et Optimisations​

Flux optimisés​

  1. Validation d'instance : < 500 ms (pas d'auth, requête simple)
  2. MutationObserver : détection événementielle, pas de polling
  3. Nouvel onglet : forceview=1 évite la page intermédiaire (un seul clic)

Goulots d'étranglement potentiels​

  1. Génération JWT : signature RSA (~50-100 ms)
  2. Webservice Moodle : core_course_get_contents peut être lent pour les gros cours
  3. Traitement document : conversion PDF/Office (variable selon la taille)
